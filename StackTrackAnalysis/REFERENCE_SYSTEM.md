# StackTrack Reference System

## Reference Product

- **Product:** StackTrack
- **Reference website:** https://stacktrack.thewssa.com/
- **Purpose:** business-workflow reference for StackMeet.

## Evidence boundary

This analysis does not copy source code, reverse engineer implementation, bypass authentication, or reproduce StackTrack architecture. It includes authorized, read-only inspection of the active competition selected by the owner. The reviewed navigation exposed settings, event configuration, individual/doubles/relay registration, prelims, finals, paperwork, reports, display, and user administration. Module notes still distinguish direct observations from StackMeet recommendations, and leave unvisited details explicitly unverified.

No usernames, passwords, sessions, or other credentials are retained in this folder.

## StackMeet design principles

1. **Competition first:** a Competition owns settings, divisions, entries, teams, results, and outputs.
2. **SQL native:** operational data belongs in SQL, not browser state.
3. **Operator first:** minimize clicks and typing; support keypad-led competition entry.
4. **Consistency:** one entry workflow, one print standard, one dashboard.
5. **Continuous improvement:** reproduce proven business outcomes, not another product's UI or code.

## Reading these documents

- **Observed Behaviour** means directly visible public behaviour, user-provided material, or explicitly marked inference.
- **Recommended StackMeet Design** is independent product design; it is not a claim about StackTrack.
