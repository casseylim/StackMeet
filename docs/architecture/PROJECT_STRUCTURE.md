# Current Project Structure

## Runtime model

StackMeet is a static browser SPA with no build step, package manifest, server runtime, or connected database. `index.html` loads `styles.css`, bundled import data, and `app.js` directly.

```text
StackMeet/
|-- index.html
|-- app.js
|-- styles.css
|-- README.md
|-- CHANGELOG.md
|-- ROADMAP.md
|-- ARCHITECTURE.md
|-- ARCHITECTURE_REVIEW.md
|-- BUSINESS_RULES.md
|-- TODO.md
|-- PROJECT_SETUP_REPORT.md
|-- assets/
|   |-- competition-banner.png
|   `-- stackmeet-logo.png
|-- data/
|   `-- stacktrack-4257-stackers.js
|-- database/
|   |-- README.md
|   |-- schema.sql
|   |-- seed.sql
|   |-- stackmeet_erd.svg
|   |-- MULTI_TOURNAMENT_MODEL.md
|   `-- XML_TO_SQL_MAPPING.md
|-- docs/
|   `-- architecture/       Sprint 1 design documents
|-- backups/                Manual backup staging
|-- exports/                Export staging
|-- releases/               Packaged releases
|-- screenshots/            UI/QA references
`-- temp/                   Disposable development work
```

## Root files

| File | Purpose | Dependencies |
|---|---|---|
| `index.html` | Application shell, toolbar, route templates, forms, and script/style references. | `styles.css`, `assets/*`, `data/stacktrack-4257-stackers.js`, `app.js`. Its DOM IDs/templates are direct dependencies of `app.js`. |
| `app.js` | Defaults, global state, business rules, rendering, events, persistence, XML, reports, exports, and printing. | Browser DOM, Web Storage, Blob/URL, DOMParser, Crypto APIs, `window.stackmeetImport4257`, HTML IDs, and CSS classes. |
| `styles.css` | Screen layout, components, tables, reports, responsive rules, and print styling. | HTML classes and markup generated by `index.html`/`app.js`. |
| `README.md` | Repository overview and run instructions. | Documentation only. |
| `CHANGELOG.md` | Release/change history. | Release process. |
| `ROADMAP.md` | Engineering and product phases. | Planning only. |
| `ARCHITECTURE.md` | Concise current/future architecture overview. | Points to the detailed review. |
| `ARCHITECTURE_REVIEW.md` | Sprint 0 dependency, debt, risk, and roadmap analysis. | Architecture reference. |
| `BUSINESS_RULES.md` | Current competition/workflow rules. | Product and test reference. |
| `TODO.md` | Engineering/workflow backlog. | Planning only. |
| `PROJECT_SETUP_REPORT.md` | Official repository migration evidence. | Audit documentation. |

## Folders and supporting files

### `assets/`

- `competition-banner.png`: dashboard/competition branding.
- `stackmeet-logo.png`: logo, favicon, and touch icon.

### `data/`

- `stacktrack-4257-stackers.js`: defines `window.stackmeetImport4257`; must load before `app.js` and is consumed by `applyStartupImport()`.

### `database/`

These files are design inputs only and are not loaded at runtime.

| File | Purpose | Dependency |
|---|---|---|
| `README.md` | Database structure overview. | References the schema documents. |
| `schema.sql` | Proposed multi-tournament relational schema and indexes. | Future SQL engine. |
| `seed.sql` | Initial event/stage lookup rows. | Tables from `schema.sql`. |
| `stackmeet_erd.svg` | Entity-relationship diagram. | Mirrors the proposed schema. |
| `MULTI_TOURNAMENT_MODEL.md` | Competition ID, login, scoping, and stage model. | Future API/backend guidance. |
| `XML_TO_SQL_MAPPING.md` | Current XML/state to SQL mapping. | Current XML and proposed schema. |

### `docs/architecture/`

Design-only documents covering decisions, structure/state, proposed services, extraction order, and coding standards. They are not runtime dependencies.

### Operational folders

`backups/`, `exports/`, `releases/`, `screenshots/`, and `temp/` are currently manual staging locations. Browser code does not write to them.

## Dependency summary

```text
index.html ---> styles.css
     |-------> assets/*
     |-------> data/stacktrack-4257-stackers.js
     `-------> app.js <------- bundled import global
                    |--------> browser DOM/Web APIs
                    `--------> localStorage and XML upload/download

database/* and docs/*: no runtime dependency
```
