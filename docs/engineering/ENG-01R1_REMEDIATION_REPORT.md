## CI startup investigation

[Run 45381374892](https://github.com/casseylim/StackMeet/actions/runs/45381374892/job/138400961823) tested de242453. GitHub job metadata confirms the Release build and LocalDB start succeeded. CoreIntegrity reported an exited HTTP child without an HTTP response. The old harness redirected stdout and stderr without reading either stream. Its readiness loop swallowed connection failures and omitted the exit code. The GitHub log download disconnected during this review, and the historical exit cause remains unverified.

The revised CoreIntegrity harness verifies the Release DLL exists and runs it directly from the application content root. Kestrel binds an OS-assigned loopback port. The harness consumes both output streams, observes the listening address and process exit, and checks the SQL-backed state endpoint. Early exits include the exit code and captured output. The local run reached that endpoint and cleaned up its synthetic database. The CI workflow also enables the existing cloud build/test gates on the ENG-01 review branch.

## Compatibility, acceptance and rollback

Release the API, application shell and versioned browser scripts as a coordinated set under the existing release governance. Cached clients receive 428 until they reopen or upgrade the scoring screen. Offline and legacy JSON entry require no new endpoint. A client lost after sending a request cannot infer its outcome from the connection alone. Review the current stored values before taking another action. Confirmed saves still require review when the post-save refresh fails.

Acceptance requires hosted branch checks and the isolated combined Phase 1 evidence, plus reviewer confirmation of mixed-client rollout and operator comprehension in each locale. The executable editor tests use a lightweight DOM fixture. They do not establish every assistive-technology behavior or reconstruct a draft after a full browser reload. Reviewed baselines live for the open editor. Competing external writes can still invalidate them and trigger another review.

Rollback is a reviewed revert of the coordinated API and browser changes, including cache keys, followed by a fresh governed build. This restores the previous online contract and its compatibility risk. No schema change is required. Scoring interpretation and historical certified snapshots remain outside this remediation.
