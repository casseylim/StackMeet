## Source and dependency assessment

The deployment unit is a modular monolith. ASP.NET Core routes requests through path-based authentication and competition-specific authorization to EF Core and SQL Server. The browser loads ordered scripts, stores a competition snapshot and reconciles SQL participants and results through providers. Result mutations increment a competition revision and notify SignalR groups after commit. Public results reconstruct a view from SQL, JSON and asset metadata. Public career profiles use separate identity, historical placement and publication contracts. XML, the portable competition package, the SQL backup and the release rollback bundle each cover a different recovery unit.

The [inventory](evidence/inventory.md) covers all 511 tracked baseline files. Lexical decision totals cover 123 first-party C# and JavaScript units, excluding generated migrations, vendor and test files. They include matching text in comments and strings. The [internal dependency map](evidence/dependencies.md) uses C# declaration/name co-occurrence and HTML script order. These edges include ambiguous names and omit reflection, callbacks, implicit DI and dynamic imports. The [resolved API package graph](evidence/packages.md) contains 81 target entries. EF tooling is private to the build. The graph includes design-time dependencies. Check runtime reachability per package before prioritizing a patch.

The [JavaScript parser measurements](evidence/complexity.md) identify a 76-point delegated click handler at wwwroot/app.js:4774. It selects routing, persistence and rendering actions for unrelated screens. Roslyn parsed 400 method declarations. The [highest C# scores](evidence/csharp-complexity.json) include the 34-point result batch at Controllers/CompetitionResultsController.cs:30. The C# metric counts one per method, condition, logical AND/OR, loop, catch, non-default switch label and switch-expression arm, including nested syntax. Properties, constructors and top-level local functions are outside that denominator.

The [duplication scan](evidence/duplication.md) found 218 distinct cross-file windows of ten nonblank, trimmed source lines with at least 240 characters, omitting comment-only lines beginning with //, /* or *. Adjacent windows overlap. The shared identity lookup across four career services is a candidate for characterization before extraction. Publication eligibility and evidence requirements differ by service. Similar text alone does not establish interchangeable behavior.

Release build emitted CS8620, CS8714 and CS8621 at Activities/SportStacking/Ranking/FinalsHistoricalPlacementProjectionService.cs:296 and :302. The filter selects valid rows, but the nullable tie-key type flows into sorting and dictionary construction. **Medium, verified compiler diagnostics.** A malformed internal valid row could interrupt projection. An observed historical data failure has not been established. Encode the valid-row invariant, test scratch and missing keys and preserve the snapshot contract. A read-only solution analyzer pass for CA1812, CA1822 and CA1801 produced an empty format report at configured severity. Framework discovery, DI and browser globals preclude an unused-code clearance.
