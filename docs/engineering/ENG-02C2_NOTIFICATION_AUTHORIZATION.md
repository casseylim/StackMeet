# ENG-02C2 — Reauthorization before notification fanout (draft)

Base: 4494294cf0e1649fffe28c65fe404cdf8c8a1d53. Stacked on ENG-02C1 while its hosted validation is pending. Scope: replace unchecked group sends in the three identified state/result controllers with current recipient authorization. This is a development candidate, not release approval.

The process-local concurrent registry records one subscription per connection and removes it on switch/disconnect. It retains only competition key, connection ID, expiration and minimal authorization facts; no bearer, display name or email. The scoped notification service rechecks competition existence, archive and listing state, token expiry, account activity/session version/admin flag and role assignments before every change notification. Public subscriptions require listing; legacy scoped operators retain access until their token expires or the competition is archived. Account reads are batched in chunks of 500. A failed authorization query sends nothing; the existing post-commit logging guards preserve the saved result.

The same change metadata payload and polling fallback remain. Unauthorized subscriptions are removed lazily at fanout, not forcibly disconnected. Rejoin requires authorization. An already-authorized notification in flight cannot be recalled; concurrent database changes after the check or a switch racing the final send are not transactionally serialized with transport delivery. No exact-time disconnect guarantee is claimed. Legacy competition password rotation is not a revocation mechanism under the existing token format. Multi-instance registry/fanout, connection budgets, automatic rejoin after reauthorization and load/latency measurement remain separate work.

Tests extend the isolated loopback protocol harness: positive public and assigned-viewer notifications, then negative delivery after unlisting, assignment removal and logout-all while the socket stays connected. Each completed write is followed by an invocation completion barrier. Existing C1 and HTTP integrity tests remain. Hosted results pending. Production publication rules, historical results, database schema and configuration are unchanged. Before acceptance validate C1/C2 hosted checks, browser fallback, topology and performance. No deploy or merge into master.
