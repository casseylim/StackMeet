# ENG-05B — State save and draft protection candidate

Base: ENG-05A 0eb1a7b2c15127026c87574070611a463c0366c1, [CI 45964721024](https://github.com/casseylim/StackMeet/actions/runs/45964721024) passed all three jobs. New hosted CI pending.

## Implementation

- ApiProvider.observe reads a background state document and ETag without accepting the ETag. An observation is bound to the originating provider and its accepted revision at read start. acceptObservation rejects a changed baseline, another provider, missing/invalid revision or a regressing numeric ETag. BigInt comparison preserves bigint revision precision. Existing explicit reloadLatest API and initial load/save contract remain available.
- Operator background loadLatestCompetition now observes rather than rebases. State application is deferred while an editor/input is active, a state save is queued or in-memory failed/newer draft is retained. Normalize before accepting the observed revision. Keep SQL-owned stackers/results separate. A previously deferred observation cannot overwrite a later accepted write.
- Save queue captures a generation. A failure invalidates previously queued generations, and ambiguous/stale/authorization failures require review before another write. A known HTTP 400 rejection can be manually corrected and submitted again; queued requests from the failed generation still cannot proceed. Preserve tombstones until acknowledged by a successful write. Merge result into runtime state only after successful POST and only if the projected local state has not changed since the captured request. A successful earlier write does not acknowledge newer local edits.
- Review saved state button appears when failed/newer draft retained. No automatic POST or replay. If the observed server revision still matches the accepted baseline, explicit confirmation permits a separate manual retry. If revision changed and the saved state differs from local draft, explicit confirmation is required before replacing the local state; cancel retains draft and tombstones. If state already matches, accept the authoritative revision without another write. Reviewed replacement preserves SQL-owned slices and clears acknowledged/discarded local tombstones. Failed observation leaves the draft protected.
- Beforeunload guard warns on queued or failed/newer in-memory state saves. No new persistent storage of sensitive drafts or credential material.

## Boundaries

This increment protects recognized editors, focused inputs, queued writes and failed/newer in-memory drafts, not every untracked DOM edit after focus leaves. Review is conservative: no automatic three-way merge or user-facing field-difference editor; changed baseline with a differing draft requires either keeping the draft blocked or explicitly discarding it to load the saved state. The operator must manually re-enter desired edits after a confirmed discard. Browser reload/logout or forced navigation may still lose in-memory drafts; beforeunload is best effort, not durable persistence. Full reauthentication/close-during-edit workflows, language review of new messages, accessibility and actual browser/network validation remain open. Explicit reloadLatest compatibility API is not removed, but no longer used by operator background refresh. The previously observed operator applied-watermark, independent SQL reconnect refresh, public coalescing and withdrawal gaps remain for ENG-05C/D. No claim of production readiness.

Overall/All-Around = Finals only. Historical certified snapshot bytes/digests immutable. No master merge or production deployment. Production IIS web.config must never be overwritten in upload, sync or rollback; secure backup and identical pre/post SHA-256 mandatory.
